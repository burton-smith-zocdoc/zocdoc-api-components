# Alert

Communicates the state of a surface — a page, a card, a dialog. Use it for information that
should persist until the person acts on it, not for something that needs immediate attention.

## Default

The alert is hidden until `open` is set.

<code-bubble>

```html
<zd-alert open>Your appointment has been booked.</zd-alert>
```

</code-bubble>

## Severity

Use `variant` to say what kind of message this is: `info`, `success`, `warning`, or `danger`.
Each one tints the surface, tints the border, and draws its own icon. Omit it for an alert with
no severity, which keeps the neutral surface and draws no icon.

<code-bubble>

```html
<zd-alert open variant="danger" heading="Booking failed">
  We couldn't complete your booking.
</zd-alert>
```

</code-bubble>

The tint is a light step of the ramp rather than a solid fill, so a control in the `action` slot
still reads on top of it — a `secondary` button on a solid red surface would not. The text color
is generated against the tint, so it meets AA in both color schemes.

`variant` and `politeness` are independent. `variant` is how the alert looks; `politeness` is
whether and how it is announced. An error usually wants both `variant="danger"` and
`politeness="assertive"`, but a `danger` alert that has been on the page all along should stay
`polite`.

## Heading

Use the `heading` attribute — or the `heading` slot for rich content — to title the alert.

<code-bubble>

```html
<zd-alert open heading="Limited availability">
  This provider has no openings for the next two weeks.
</zd-alert>
```

</code-bubble>

## Dismissible

Use the `dismissible` attribute to add a close button.

<code-bubble>

```html
<zd-alert open dismissible heading="Booking failed">
  We couldn't complete your booking. Please try again.
</zd-alert>
```

</code-bubble>

## Actions

Use the `action` slot for controls.

<code-bubble>

```html
<zd-alert open dismissible heading="Insurance not verified">
  We couldn't confirm your plan with this provider.
  <zd-button slot="action" variant="secondary" size="small">Update insurance</zd-button>
  <zd-button slot="action" variant="ghost" size="small">Continue anyway</zd-button>
</zd-alert>
```

</code-bubble>

## Icon

Each severity draws its own icon: `info-circle`, `checkmark-circle`, `warning`, and
`error-circle`. Use the `icon` slot to replace it, or to give an alert with no severity an icon.

<code-bubble>

```html
<zd-alert open variant="warning" heading="Insurance not verified">
  <zd-icon slot="icon" name="warning-shield"></zd-icon>
  We couldn't confirm your plan with this provider.
</zd-alert>
```

</code-bubble>

The severity's own icon is decorative — it carries no label, because the severity is already in
the message text. A slotted icon should stay decorative for the same reason: don't give it a
`label` unless it says something the text does not.

## Showing and hiding from script

The alert exposes `show()`, `hide()`, and `toggle()`, and emits `alert-show`, `alert-after-show`,
`alert-hide`, and `alert-after-hide`. The `after-*` events fire once the transition finishes.
Button invokers work too — see the button docs.

<code-bubble>

```html
<zd-button toggles="booking-alert">Toggle alert</zd-button>
<zd-alert id="booking-alert" dismissible>Your appointment has been booked.</zd-alert>
```

</code-bubble>

Retime the show/hide transition with the `--zd-alert-transition` custom property.

```css
zd-alert {
  --zd-alert-transition: 200ms ease-out;
}
```

# Accessibility

An alert that appears in response to something the person did needs to be announced, and
`politeness` is what does it (A11Y-002). It renders the live region on the alert itself:
`polite` gives `role="status"`, `assertive` gives `role="alert"`, and `off` gives neither.
`polite` is the default.

<code-bubble>

```html
<zd-alert open politeness="polite" heading="Appointment booked">
  You'll get a confirmation email shortly.
</zd-alert>
```

</code-bubble>

Use `assertive` for failures, so the message interrupts rather than waiting for a pause. A live
region only announces content that changes while it is on the page, so an alert already rendered
at page load is not announced no matter what `politeness` says — that case is `off`.

Color is not the severity. Each variant draws an icon so the distinction survives a monochrome
display, but the message text still has to say what happened; `variant="danger"` alone tells a
screen reader nothing.

Never put patient data in the message — describe the action that failed, not the values that were
submitted (PHI-001).
