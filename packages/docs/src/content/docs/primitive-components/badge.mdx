A badge adds a compact label or status alongside other content. The text should communicate the status by itself: `variant` is visual styling and does not give assistive technology additional meaning.

## Usage

### Status labels

```html preview
<zd-flex gap="8" wrap>
  <zd-badge variant="neutral">Draft</zd-badge>
  <zd-badge variant="info">Updated</zd-badge>
  <zd-badge variant="success">Available</zd-badge>
  <zd-badge variant="warning">Review needed</zd-badge>
  <zd-badge variant="danger">Unavailable</zd-badge>
</zd-flex>
```

Choose a variant for visual emphasis, but include the actual status in the badge text. Do not communicate state using color alone.

### Add context with icons

```html preview
<zd-flex gap="8" wrap>
  <zd-badge variant="info"><zd-icon slot="start" name="calendar" label="Calendar"></zd-icon>Updated today</zd-badge>
  <zd-badge variant="success"><zd-icon slot="start" name="checkmark" label="Complete"></zd-icon>Verified</zd-badge>
</zd-flex>
```

Use the `start` or `end` slot for a supporting icon. Keep the visible badge text meaningful without the icon.

## API Reference

**Class** `ZdBadge` — **Package** `@zocdoc/api-primitive-components`

### Attributes & Properties

| Attribute | Property | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `variant` | `variant` | `'info' \| 'success' \| 'warning' \| 'danger' \| 'neutral' \| 'inverse' \| 'caution' \| 'brand' \| undefined` | — | The badge's visual treatment. Omit it to use the base `badge.*` tokens. Note that a variant is styling only - it carries no meaning for assistive technology, so the badge's text has to say what the state is (A11Y-001). |
