## configureZocdoc

Call `configureZocdoc` once, before any component fetches:

```javascript
import { configureZocdoc } from '@zocdoc/api-components';

configureZocdoc({
  baseUrl: 'https://api-developer-sandbox.zocdoc.com',
  getToken: () => fetchTokenFromBackend(),
});
```

### Options

| Option | Type | Required | Description |
|--------|------|----------|-------------|
| `baseUrl` | `string` | Yes | The Zocdoc API host for your environment |
| `getToken` | `string \| () => string \| Promise<string>` | Yes | A token, or a function returning one. Called before every request |
| `transport` | `(url, init) => Promise<Response>` | No | Replaces `fetch`. Used by the [mock transport](/zocdoc-api-components/guides/testing/#mock-transport), or supply your own proxy or replay harness |

### baseUrl

Use the host that matches your credentials. Tokens only work in the environment that issued them:

| Environment | `baseUrl` |
|---|---|
| Sandbox | `https://api-developer-sandbox.zocdoc.com` |
| Production | `https://api-developer.zocdoc.com` |

Develop and test against the sandbox. It responds to the documented [test scenarios](/zocdoc-api-components/guides/testing/#test-scenarios). Switch to production only with production credentials minted by a secure backend.

### getToken

A function is called before each API request. It can be sync or async:

```javascript
// Sync
getToken: () => sessionStorage.getItem('zocdoc_token')

// Async
getToken: async () => {
  const res = await fetch('/api/token');
  const { token } = await res.json();
  return token;
}
```

Access tokens last 60 minutes, and `getToken` runs for every request, so cache the token inside it. See [Authentication](/zocdoc-api-components/getting-started/authentication/) for token flows and a caching pattern.

## Singleton Behavior

`configureZocdoc` sets global configuration. Calling it again replaces the previous config:

```javascript
configureZocdoc({ baseUrl: 'https://api-developer-sandbox.zocdoc.com', getToken: () => sandboxToken });

// Later...
configureZocdoc({ baseUrl: 'https://api-developer.zocdoc.com', getToken: () => productionToken });
// All subsequent requests use productionToken and the production host
```

Cached reference data isn't cleared when you reconfigure. Call `clearReferenceDataCache()` after switching environments:

```javascript
import { clearReferenceDataCache } from '@zocdoc/api-components';

clearReferenceDataCache();
```

## Mock Transport

For testing, use `configureZocdocMock` instead:

```javascript
import { configureZocdocMock } from '@zocdoc/api-components/mock';

configureZocdocMock();
```

This configures the client to return fixture data without making network requests. See [Testing](/zocdoc-api-components/guides/testing/) for details.

## Timing

Configure the client as early as possible. Components that fetch on their own, such as `<zd-provider-search>` loading specialties, wait until the client is configured. A request you trigger by setting a property fails immediately if the client isn't configured yet. A common pattern:

```javascript
// config.js
import { configureZocdoc } from '@zocdoc/api-components';

export function initZocdoc() {
  configureZocdoc({
    baseUrl: import.meta.env.VITE_ZOCDOC_URL,
    getToken: () => getStoredToken(),
  });
}
```

```javascript
// main.js
import { initZocdoc } from './config.js';
import '@zocdoc/api-components';

initZocdoc();
// Now safe to render components
```
