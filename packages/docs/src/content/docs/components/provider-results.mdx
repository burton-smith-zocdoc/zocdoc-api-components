The `<zd-provider-results>` component renders a paginated list of providers with optional availability previews.

## Usage

Pass provider data as JavaScript properties; HTML attributes cannot carry object arrays. This preview uses a documented mock provider with a photo served from the docs site:

```html preview
<zd-provider-results id="provider-results" total-count="1"></zd-provider-results>
<script>
  const providerResults = document.getElementById('provider-results');
  providerResults.providers = [
    {
      provider_location_id: 'pr_abc123-def456_wxyz7890|lo_abc123-def456_wxyz7890',
      provider_location_type: 'in_person_provider',
      accepts_patient_insurance: 'accepted',
      provider: {
        provider_id: 'pr_abc123-def456_wxyz7890',
        first_name: 'Avery',
        last_name: 'Sandoval',
        title: 'MD',
        specialties: ['Primary Care Doctor'],
        provider_photo_url: '/zocdoc-api-components/images/michael-scott.png',
      },
      location: {
        address1: '1 Sandbox Plaza',
        city: 'Brooklyn',
        state: 'NY',
        zip_code: '11201',
        distance_to_patient_mi: 0.8,
      },
    },
  ];
</script>
```

### Loading

```html preview
<zd-provider-results loading page-size="3"></zd-provider-results>
```

The list never fetches, so set `loading` while the search or the next page is in flight and clear it when the new `providers` arrive. It shows one skeleton card per `page-size` slot instead of the "no providers" message, keeps the pager in place but disabled, and announces "Loading providers" once for the whole list.

## Zocdoc API

Renders a page of `GET /v1/provider_locations` results. Paging follows the API's zero-based `page` and its `page_size` (default 10). See the [Zocdoc API overview](/zocdoc-api-components/guides/zocdoc-api/).

## Accessibility

- Results announced via `aria-live` region
- Each card is focusable and activates on Enter/Space
- Pagination controls labeled for screen readers
