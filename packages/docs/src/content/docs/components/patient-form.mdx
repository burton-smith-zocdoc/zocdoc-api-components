The `<zd-patient-form>` component collects required patient information for booking an appointment.

## Usage

```html preview
<zd-patient-form></zd-patient-form>
```

## Fields

The form collects:

- First name
- Last name
- Date of birth
- Sex at birth
- Phone number
- Email address
- Address (street, city, state, ZIP)
- Insurance member ID (only when a plan is set or the provider location requires one)
- Notes (optional)

## Insurance

Set two properties so the form collects what the provider location needs. `<zd-booking>` sets both for you:

| Property | Type | Description |
|---|---|---|
| `insurancePlanId` | `string` | The plan chosen during search. Sent as `patient.insurance.insurance_plan_id`, and shows the member ID field |
| `requiredFields` | `string[]` | The selected location's `booking_requirements.required_fields`, as the API returns them |

Both are properties only (`.insurancePlanId=`, `.requiredFields=`), never attributes, because insurance details are PHI.

When `requiredFields` includes:

- `data.patient.insurance.insurance_member_id`: the member ID field becomes required.
- `data.patient.insurance.insurance_plan_id` and no plan is set: the form shows a notice asking the patient to go back and choose a plan, and won't submit. It has no plan picker of its own.

```javascript
const form = document.querySelector('zd-patient-form');
form.insurancePlanId = 'ip_9111';
form.requiredFields = location.booking_requirements?.required_fields ?? [];
```

To try both states in the sandbox or the mock, use the `pr_insuranceIdIsRequired|lo_insuranceIdIsRequired` [test scenario](/zocdoc-api-components/guides/testing/#test-scenarios).

## Events

| Event | Detail | Description |
|-------|--------|-------------|
| `patient-submit` | `{ patient: Patient, notes?: string }` | Form submitted with valid data |

`patient.insurance` is included only when a plan is set.

The event detail contains all patient fields. **This is PHI** — only send it to your configured Zocdoc `baseUrl`.

## Zocdoc API

Collects the `patient` object for `POST /v1/appointments`. Every field is PHI: the form never logs values or puts them in error messages. Some provider locations list `booking_requirements`, such as insurance member and plan IDs. The API rejects a booking that omits them with a `400`, so the form requires them up front (see [Insurance](#insurance)). For the request schema, see the [API Reference](https://api-docs.zocdoc.com/apis).

## Accessibility

- All fields have visible labels
- Required fields marked with asterisk and `aria-required`
- Validation errors linked via `aria-describedby`
- Related fields grouped in fieldsets (e.g., address)

## Validation

Client-side validation runs on submit:

- Required fields must be filled
- Email must be valid format
- Phone must be 10 digits
- Date of birth must be valid and in the past

Server-side validation may return additional errors, displayed inline.
