The `<zd-provider-search>` component collects search criteria and fetches matching providers from the API.

## Usage

```html preview
<zd-provider-search zip-code="11201" specialty-id="sp_153"></zd-provider-search>
```

## Examples

### Pre-filled Insurance

```html preview
<zd-provider-search zip-code="11201" insurance-plan-id="ip_9111"></zd-provider-search>
```

### With Specialty

```html preview
<zd-provider-search zip-code="11201" specialty-id="sp_153"></zd-provider-search>
```

## Zocdoc API

Loads specialties, visit reasons, and insurance plans from the [reference data](https://api-docs.zocdoc.com/guides/reference-data) endpoints, then searches `GET /v1/provider_locations`. A ZIP code is required. Sandbox ZIPs `11201` (results), `99734` (empty), and `10112` (error) drive each state. See [Test Scenarios](/zocdoc-api-components/guides/testing/#test-scenarios).

## Supplied Data and Markup

Set the `supplied` attribute when your page makes its own API calls. The component then calls no API at all. A submit or page change emits `provider-search-request` with the validated criteria instead of searching. Set `loading` while you fetch, and give the results to your own `zd-provider-results`.

Set `specialties` and `insurancePlans` by script, or write them as JSON blocks. With `supplied` set, a list you leave out stays empty. Without it, the component fetches any list you leave out, including one you set back to `undefined`:

```html preview
<zd-provider-search supplied zip-code="11201" specialty-id="sp_153">
  <script type="application/json" data-zd-prop="specialties">
    [
      {
        "id": "sp_153",
        "name": "Primary Care Doctor",
        "care_category": "health",
        "default_visit_reason_id": "pc_FRO-18leckytNKtruw5dLR",
        "default_visit_reason_name": "New patient visit"
      },
      {
        "id": "sp_154",
        "name": "Dentist",
        "care_category": "dental",
        "default_visit_reason_id": "pc_TlZW-r06U0W3pCsIGtSI5B",
        "default_visit_reason_name": "New patient cleaning"
      }
    ]
  </script>
  <script type="application/json" data-zd-prop="insurancePlans">
    [
      {
        "id": "ip_9111",
        "name": "Sandbox National PPO",
        "status": "active",
        "care_categories": ["health"],
        "coverage_area": { "is_national": true, "states": [] }
      }
    ]
  </script>
</zd-provider-search>
```

Nothing is fetched. Submitting emits `provider-search-request` instead of searching. See [Markup and Supplied Data](/zocdoc-api-components/guides/markup-and-supplied-data/).

## Accessibility

- Form fields have visible labels
- An invalid field is marked `aria-invalid` and linked to its own message with `aria-describedby`
- Submit button disabled while a search is in flight
- While searching, two placeholder provider cards with loading availability grids stand in for results. They are hidden from assistive technology and marked `aria-busy`, and a single polite status region outside them announces "Searching…" instead
- Skeleton shimmer stops under `prefers-reduced-motion: reduce`
