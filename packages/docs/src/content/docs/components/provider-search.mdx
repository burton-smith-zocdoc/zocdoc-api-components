The `<zd-provider-search>` component collects search criteria and fetches matching providers from the API.

## Usage

```html preview
<zd-provider-search
  zip-code="11201"
  specialty-id="sp_153"
></zd-provider-search>
```

## Examples

### Pre-filled Insurance

```html preview
<zd-provider-search
  zip-code="11201"
  insurance-plan-id="ip_9111"
></zd-provider-search>
```

### With Specialty

```html preview
<zd-provider-search
  zip-code="11201"
  specialty-id="sp_153"
></zd-provider-search>
```

## Attributes

| Attribute | Type | Default | Description |
|-----------|------|---------|-------------|
| `zip-code` | `string` | — | Pre-fill ZIP code |
| `specialty-id` | `string` | — | Pre-select specialty |
| `insurance-plan-id` | `string` | — | Pre-select insurance plan |
| `insurance-name` | `string` | — | Display name for insurance |

## Events

| Event | Detail | Description |
|-------|--------|-------------|
| `provider-results` | `{ providers, totalCount, page, pageSize, searchParameters, zipCode, specialtyId?, insurancePlanId?, insurancePlanName?, visitType? }` | Search returned results and the criteria used |
| `provider-search-error` | `{ error }` | Search failed |

## Zocdoc API

Loads specialties, visit reasons, and insurance plans from the [reference data](https://api-docs.zocdoc.com/guides/reference-data) endpoints, then searches `GET /v1/provider_locations`. A ZIP code is required. Sandbox ZIPs `11201` (results), `99734` (empty), and `10112` (error) drive each state. See [Test Scenarios](/zocdoc-api-components/guides/testing/#test-scenarios).

## Accessibility

- Form fields have visible labels
- Error messages linked via `aria-describedby`
- Submit button disabled during loading with `aria-busy`
