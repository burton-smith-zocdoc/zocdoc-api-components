# I18N-003: Use CSS logical properties for RTL

Use CSS logical properties instead of physical directional properties. This ensures proper layout in right-to-left languages.

Charm primitives already use logical properties; API component styles must do the same.

| Physical | Logical |
|----------|---------|
| `margin-left` / `margin-right` | `margin-inline-start` / `margin-inline-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `left` / `right` | `inset-inline-start` / `inset-inline-end` |
| `text-align: left` | `text-align: start` |
| `border-left` | `border-inline-start` |
| `float: left` | `float: inline-start` |

**Do:**

```css
.provider-card {
  padding-inline: var(--zd-spacing-4);
  margin-block-end: var(--zd-spacing-2);
  text-align: start;
  border-inline-start: 3px solid var(--zd-color-primary);
}

.search-icon {
  inset-inline-end: var(--zd-spacing-2);
}
```

**Don't:**

```css
/* ❌ Physical properties — breaks in RTL */
.provider-card {
  padding-left: var(--zd-spacing-4);
  padding-right: var(--zd-spacing-4);
  margin-bottom: var(--zd-spacing-2);
  text-align: left;
  border-left: 3px solid var(--zd-color-primary);
}

.search-icon {
  right: var(--zd-spacing-2);
}
```

Exception: `top`/`bottom` are fine when the direction is truly vertical (not dependent on reading direction).
