# I18N-002: Use Intl APIs for dates, times, and numbers

The booking flow displays dates (availability), times (appointment slots), and phone numbers. Format these with `Intl` APIs, not string concatenation.

**Do:**

```ts
// Date formatting
const dateFormatter = new Intl.DateTimeFormat(undefined, {
  weekday: 'short',
  month: 'short',
  day: 'numeric',
});
const dateStr = dateFormatter.format(new Date(slot.start_time));
// "Fri, Aug 15" in en-US, locale-appropriate elsewhere

// Time formatting
const timeFormatter = new Intl.DateTimeFormat(undefined, {
  hour: 'numeric',
  minute: '2-digit',
});
const timeStr = timeFormatter.format(new Date(slot.start_time));
// "9:30 AM" in en-US, "09:30" in de-DE

// Relative time (if showing "in 2 days")
const relativeFormatter = new Intl.RelativeTimeFormat(undefined, {
  numeric: 'auto',
});
const relativeStr = relativeFormatter.format(2, 'day');
// "in 2 days"
```

**Don't:**

```ts
// ❌ Hardcoded format — wrong for non-US locales
const dateStr = `${date.getMonth() + 1}/${date.getDate()}/${date.getFullYear()}`;

// ❌ Hardcoded AM/PM — 24-hour locales use different format
const timeStr = `${hours % 12 || 12}:${minutes.toString().padStart(2, '0')} ${hours >= 12 ? 'PM' : 'AM'}`;

// ❌ Hardcoded phone format — international numbers differ
const phone = `(${area}) ${prefix}-${line}`;
```

Pass `undefined` as the first argument to use the user's locale. Explicitly pass a locale only when displaying in a specific locale (e.g., provider's local time).
