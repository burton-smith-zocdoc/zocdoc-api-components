# A11Y-001: WCAG 2.2 AA conformance target

All components must conform to WCAG 2.2 Level AA. Charm primitives already meet this; our API components must not regress it.

Key success criteria for a booking flow:

| Criterion | Applies to |
|-----------|------------|
| 1.3.1 Info and Relationships | Form labels, fieldsets, error association |
| 1.4.3 Contrast (Minimum) | All text, including error messages |
| 2.1.1 Keyboard | Full flow completable without a mouse |
| 2.4.3 Focus Order | Multi-step flow follows logical sequence |
| 3.3.1 Error Identification | Errors described in text, not just color |
| 3.3.2 Labels or Instructions | Every form field has a visible label |
| 4.1.2 Name, Role, Value | Custom elements expose correct ARIA |

**Do:**

```ts
// Every component test includes axe
describe('Accessibility', () => {
  it('has no axe violations', async () => {
    const { container } = await render(<ZdProviderSearch />);
    expect(await axe.run(container)).toHaveNoViolations();
  });
});
```

**Don't:**

```ts
// ❌ Skipping accessibility tests
describe.skip('Accessibility', () => { ... });

// ❌ Suppressing violations without fixing
expect(await axe.run(container, { rules: { 'color-contrast': { enabled: false } } }))
```
