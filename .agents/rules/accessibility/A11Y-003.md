# A11Y-003: Manage focus in multi-step flows

When the booking flow advances to a new step, focus must move to a sensible target — typically the first interactive element or a heading announcing the new step.

**Do:**

```ts
async #advanceToStep(step: BookingStep) {
  this.currentStep = step;
  await this.updateComplete;
  
  // Focus the step heading or first interactive element
  const target = this.shadowRoot?.querySelector<HTMLElement>(
    `[data-step="${step}"] h2, [data-step="${step}"] input, [data-step="${step}"] button`
  );
  target?.focus();
}

// When a dismissible closes, return focus to opener
#handleConfirmationClose() {
  this.confirmationOpen = false;
  this.openerButton?.focus();
}
```

```ts
// Template with focusable step headings
render() {
  return html`
    <section data-step="availability">
      <h2 tabindex="-1">Select an appointment time</h2>
      ...
    </section>
  `;
}
```

**Don't:**

```ts
// ❌ No focus management — user is stranded at previous location
#advanceToStep(step: BookingStep) {
  this.currentStep = step;
  // Focus stays wherever it was
}

// ❌ Focus on container — no clear target
this.shadowRoot?.querySelector('[data-step]')?.focus();
```

Headings use `tabindex="-1"` to be focusable programmatically without appearing in the tab order.
